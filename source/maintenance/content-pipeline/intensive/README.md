# 材料精读与写作前置

这里的三个 JSON 是当前38组阅读精读的维护源。按材料ID引用原文，正文仍由原来的四份 `authentic-reading-*.json` 提供，不复制题目或学习记录。

每个单元包含逐段内容讲解、原文词块及语境用法、完整句子的句意与结构说明。不能出现题号、选项分析、答案定位或解题步骤。已有词句本继续负责收藏与后续复习；材料精读可以独立阅读，不要求先答题或提交笔记。

`writing` 的表达必须真实出现于该单元原文，可在写作例句中自然变换词形。`matches` 引用已有写作题的真实 `caseId`，同时写出贴题例句与内容关系；先读原题再判断。例句统一标示为编写示范。没有高拟合章节就留空并说明，不为覆盖 Task 1／Task 2 或每篇材料而硬配。此前删除的泛化社会责任、低成就、跨行业补贴映射不得只凭关键词重新加入。

页面由 `material_reading.py` 统一生成：阅读单元末尾是纯材料精读，写作单元题目之前是来源表达、用法与贴题例句。同一份表达的修改同时更新两个位置。阅读中的写作链接带来源ID；手动进入也只展示指定来源。

每日入口的「阅读后写作」先安排阅读作答，再精读，随后进入有真实内容关联的写作题。写作前置只显示刚读过的材料对应表达。自动配对优先有匹配题目的材料；手动指定无匹配材料时正常进入所选写作Part，不伪造关联。可以在首页自选阅读材料；长材料按所需时长限制选择。旧的四步会话按原快照继续，新阅读与关联写作允许按实际内容使用不同步骤数。

接入新资料时：先在既有内容源登记稳定ID和完整语境，再在这里增加对应精读单元及可选写作映射。维护包列表在 `material_reading.PACKS`，新增独立包时一起登记。原题变化另作内容版本；仅补讲解不能改旧题或旧作答键。

增量更新流程：

1. `integrate_material_reading.py` 检查全部段落覆盖、原文连续引用及写作目标，基于最新正式册生成候选和发布清单；不从旧整页稿重建。
2. `qa_material_reading.cjs` 检查精读入口、阅读到写作前置、无匹配、旧会话、续学及轮换；它是隔离DOM测试，不代表真实浏览器视觉验收。
3. `integrate_material_reading.py --publish` 在候选检查通过且所有输入指纹未改变时备份并写回；正式HTML最后替换。发生并行修改应重新基于最新输入构建，不能更新指纹后强行发布旧候选。

`material-reading-qa/integration.json` 逐文件记录备份与发布状态。源JSON、随册JSON和SQLite里的相关派生字段一并更新；跨文件发布不是数据库事务，失败时根据清单恢复或继续检查，不能宣称整批已完成。
