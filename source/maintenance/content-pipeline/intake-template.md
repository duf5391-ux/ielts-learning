# 新资料接入工作表

复制到 `content-pipeline/batches/<batch-id>/intake.md`，由助手填写。用户不需要写表或JSON。这是设计工作表，不可直接导入学习页面。

## 1. 这次收到什么

- 批次ID：
- 标题／收到日期：
- 用户原始要求（原文）：
- 判断的主要用途及依据：
- 已知限制：时间、目标、用途；未提供的不要编造：
- 当前状态：received / extracted / designed / validated / published；可分单元记录：
- 本批处理范围：已设计／待处理／待核验；大资料的优先小批与后续提纲：
- 同一原件或不同扫描件的比对依据：SHA-256、原题ID、页码／时间位置；冲突说明如何保留出处：

|---|---|---|---|---|---|---|
| | | | | | | |

原件归档于本批目录或引用已存在原件，不复制存量大型媒体。提取文本、修改建议和原件分开。

## 2. 怎样拆成学习单元

| unitId＋版本 | 明确目标 | 主板块／关联板块 | 所需fragmentRefs与完整上下文 | 新增／复用／仅归档 | 为什么这样拆 | 不覆盖什么 |
|---|---|---|---|---|---|---|
| | | | | | | |

在此说明哪些材料不适合目标、哪些语义还不明确，避免为完整表格强行制造四科内容。

## 3. 每个单元里的活动

| activityId＋版本 | 目标／阶段 | 材料与题干所在文件 | 学习动作与输出 | 完成条件（可选笔记不作必填） | 答案／参考／核对依据 | min／estimated分钟 | 必要前置条件 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

- 原题、摘录、教学改编、自编任务分别标清；改编保留了什么、变了什么：
- 有不同合理答案时的接受标准：
- 媒体与转写、题号、时间范围的配对：
- 做完后的材料精读：对应原段／音频范围、内容与观点归属、值得解释的词块／长句／指代／篇章关系、讲解所在文件、已有精读的复用与缺口；不要用解题步骤或泛泛回想替代：
- 精读后可收藏的词句与已有词句本的连接（仅列真实支持的操作）；预计用时是否已包含材料精读：
- 此题和已有材料的重复／答案接触关系：
- 真正的新情境／延迟复查安排（若需要）：
- 用户原答、首稿与修改稿的保存边界（若输入是本人作答）：
- 正文的唯一维护文件；哪些是生成索引／输出，不应手工双写：
- 新版对应旧活动／旧保存键；旧题回看入口与替代映射；无法恢复版本时的提示：

## 4. 加入哪里，怎么打开

| contentRef | 学习／练习／测试／资料／每日安排 | 真实route或待补接口 | 当前记录owner与原键／ID | 可开始条件 | 状态 |
|---|---|---|---|---|---|
| | | | | | |

标清考试Part与教学phase，不能共用同一字段。一个活动多个入口只增加映射，不复制身份。新课输出给现有定制窗口时，沿用其原课程包格式和不可变ID规则。

- 引用能否解析到指定内容版本，而不只是同名锚点：
- 原文／答案接触记录的owner、覆盖范围与seen／unseen／unknown依据；缺记录写unknown：
- 作答、接触记录和会话推进分别由谁保存；部分失败与多标签页冲突如何处理：
- 媒体状态：仅路径存在／实际可播放／远程未验证；录音是否纳入备份：

## 5. 可以怎样安排

| 时间 | 实际选择的activityRefs | 工作量与时间分配 | 暂不放入本次的内容及原因 |
|---|---|---|---|
| 15分钟 | | | |
| 30分钟 | | | |
| 60分钟 | | | |

不适合某个时段可写不适用，不强凑三个版本。隔日复查不能和当天学习合计成当场必须完成的一组。新资料是否进入自动候选池要有已发布与可打开的验证。

允许一个8分钟活动配15分钟预算，显示实际预计8分钟。工作量不能只改计时数字；续学和新偏好作用范围分清。多板块反馈中的「再练」记录到具体活动，不把整次反馈推定为各科薄弱。

## 6. 验证与写回

- 内容判断：目标匹配、上下文完整、答案成立、来源与改编清楚：
- 冷启动：从对应入口到可见且可作答的材料：
- 题目→作答→核对→退出→继续：
- 时长、可选字段、提示／答案暴露与媒体检查：
- 旧内容、字段、原记录与历史版本保留：
- 输入版本指纹、输出版本指纹、备份位置：
- 实际执行的集成器／命令；未执行的标待实施：
- 实际通过的检查与未验证范围：
- 构建／浏览器校验一致性；复用已有锚点与报告SHA检查：
- 本批发布清单：每个文件与新增资产的前后SHA、owner、逐次备份、恢复顺序；部分失败与外部改动处理：
- 实际写入的存储owner及备份覆盖范围；恢复演练结果：

发现的问题另行归类：**已证实须修正**／**接入所需的能力建设**／**可取舍的体验改进**。每项写依据、适用触发条件、实现状态及验收；不因建议更灵活就认定旧功能出错。
