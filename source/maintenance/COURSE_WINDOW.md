# 定制学习窗口：维护与课程设计约定

2026-09-20 后续接入统一阅读 [新资料内容架构](CONTENT_ARCHITECTURE.md) 和 [批次工作表](content-pipeline/intake-template.md)。本文件继续定义课程选材与现有课程包格式；新架构负责跨板块复用和每日安排。新架构中的目录、深链与记录适配是待实现项，不能直接当作本窗口已经支持的接口。

用户要求：用户发来技巧、语料、词汇或一项想达到的能力，由助手设计高度贴合的资料与练习，放入阶段化学习窗口。用户已明确纠正：**双向拟合的两端是用户提供的材料与考试**。从材料出发找它在考试中的真实用途；从考试题型、作答条件与评分要求反查材料覆盖、缺口和不适用之处。根据作答调整教学是额外的辅助机制，不能冒称为“双向拟合”的第二端。

用户进一步澄清：**重点是课程选材来源与设计本身和考试高度贴合，不是要求每批材料完整覆盖考试或保证“够用”。** 后续用户发材料后，助手围绕其内容选取相关真题、官方样例、带考官评语或可靠评分依据的作答，设计配套教学和练习。仅引用评分标准、再给任意自编例句贴上 IELTS 标签，不算高拟合选材。适用范围或待补内容仅帮助说明本课用途，不应把这项功能做成强制的全科覆盖审计。

## 用户如何使用

1. 可以直接在对话里发材料，说明想怎么用；也可以在学习册的“定制学习”保存一批材料。能力要求可单独提交，不强制先有词表。
2. 助手根据原文和考试要求设计真实课程，回填现有学习册。每课说明适用科目、题型、作答要求及对应评分维度，同时显示未覆盖部分。已有学习记录只用于辅助控制难度和负荷。原材料保存为待设计时，页面不会把固定模板假称为已经生成的定制课。
3. 学习窗口按起点小测、讲解与示范、带提示练习、独立应用、隔日复查呈现。可按 5 / 10 / 15 分钟选择当次负荷；允许跳过已会内容及提前结束。
4. 选择题提供对应答案解析；开放题提供具体核对标准、参考作答和自评，保留原答。页面不以关键词匹配代替作文批改，也不推断雅思分数。
5. “导出设计与反馈”可把本批原料、目标、答题及困难带回对话；助手据此修改讲解或设计新的迁移题。页面的下一步建议是基于已记录的作答条件，完整语义诊断由助手结合答案完成。

内置课明确标记为示例，用于说明交互；它不是用户已经提交的材料，也不是官方真题。真正的定制课必须等待实际材料或具体要求。

## 课程设计的最低要求

- 2026-09-19 后续要求：任何级别、阶段、Part 都可安排有辨析点的练习。挑选真实考试中的近义干扰、条件限制、范围变化、信息更正、图表比较和完整回应任务等，不靠生僻词或含糊题干造难度。此类补充只呈现题目与作答位置，最多提供主动展开的答案；不额外讲解、不标难度。来源与选题理由留在维护数据中。现有各科题组由 `integrate_part_practice.py` 接入，新增同类题组沿用该数据结构。

- 原始材料与教学改写分开。来源、原句或技巧存疑时，保留原文，指出具体疑点和修改理由，不把错误用法练熟。官方身份和分数只能依据可核查证据标注。
- 目标写成能观察的行为：例如“在新段落中区分因果与相关，并用不夸大的句子概括”，而非“掌握高级表达”。要求过宽时先设计能独立完成的一小段，不堆词量。
- 正向拟合：原料点 → 适用考试任务 → 需要完成的作答动作 → 针对性练习。不能把每一个词都强行塞进任意作文，也不能把技巧迁移到不适用的题型。
- 反向拟合：考试题型、限制和评分要求 → 这批原料能够支持的部分 → 缺少的能力或资料 → 补课与验收。覆盖关系需要具体到行为，不是只挂上“词汇评分”标签。未覆盖的维度、完整任务长度和时限明确列作缺口。
- 考试依据优先使用当前官方题型说明、公开评分标准、真实题目与带考官评语的样例。自行编写的题目和微练习明确标识；考点对齐不等于官方认证，微练习通过不等于达到目标分数。用户未给目标分数或当前水平时不自行编造。
- 每个材料点有解释、适用情境和不适用边界。每题通过 targets 回指材料点；反向也能找到每个材料点的练习。不能只凭目标词在题干里出现就声称覆盖。
- 词汇要练意义、搭配与语境选择；语料要练句子功能和在新情境下的重组；技巧要练决策步骤与失效边界。采用哪些训练应由实际目标决定，不机械要求所有材料做全部题型。
- 每阶段都提供可直接作答的内容，而不是“请找一段材料练习”。选择题须有唯一可辩护的答案与错项理由。开放题须有允许不同成立答案的核对标准，不能把唯一参考句当唯一正确答案。
- 小测、教学、迁移与复查使用实质不同的内容。新题必须在信息、关系或任务上变化，不能仅替换人名。独立测查前不主动展示参考答案或材料点讲解；主动查看过的帮助须记录。
- 隔日复查有建议日期和实际作答时间。同日做完只算当日练习；不声称产生了延迟保持证据。一次成功不等于全局掌握。
- 反馈必须引用真实作答与条件。错答或需帮助时回到相应材料点；提示后完成时安排独立新任务；不同日独立成功后才考虑减少同类练习，并说明这仍是局部证据。
- 课程保留用户的轻负荷偏好；不把到期复查变成必须清空的欠账，也不强制整科模考。已有学习资料可复用，必要时补齐符合任务的权威例子，但不能用来源名替代内容质量检查。

## 文件与更新方法

- `course-window.js` / `course-window.css`：交互与样式，无远程生成接口，离线可运行。
- `course-window-seed.json`：示例课程。
- `course-window-courses.json`：助手设计并发布的真实课程目录。原课程 ID 对应的内容保持不变；新版使用新 ID，避免旧作答被误套到新题上。
- `integrate_course_window.py`：只更新自身标记区域，同时增加侧栏、首页和新增资料页入口。原学习册的题面、媒体与保存字段逐字保留，并检查幂等性。写入前复读文件，避免覆盖其他任务刚完成的改动。
- 浏览器内的新材料、作答、反馈和导入课程用 `ielts-course-window-v1` 独立保存。定制学习备份与原四科学习记录分开导出，页面明确标示。

发布前先生成符合 `course-window-seed.json` 结构的课程包，并检查内容和映射。以工作区为当前目录执行：

```powershell
python integrate_course_window.py --course '新课程包.json' --check
python integrate_course_window.py --course '新课程包.json'
```

只恢复本功能入口或更新交互时：

```powershell
python integrate_course_window.py
```

更新不会直接读写用户浏览器存储。若旧的整页生成器覆盖本功能，最后运行此插入器。不要从整页备份回写主学习册。页面需要在确认本次作答已保存后重新打开或刷新。

助手应完成课程设计和回填，不要求用户自己编写 JSON。页面导入课程包是可选的便携入口。

## 课程包结构

外层为 `{ "version": 1, "courses": [...] }`。每课包含 `id, title, kind, status, requirement, sourceText, goal, minutes, items, stages, examAlignment`。真实课程不要标为 `sample`。

`items` 每项包含 `id, text, type, explanation, boundary`。`stages` 的 ID 按序为 `baseline, understand, guided, transfer, delayed`；每阶段含 `title, purpose, minutes, tasks`。每题含 `id, type, targets, prompt, reference, explanation, rubric, examTargets, examUse, practiceMode`。`choice` 题另含 `options: [{id,text}]` 和选项 ID `answer`；`text` 题使用参考作答和核对标准。材料、课程和题目 ID 均须唯一。各项解释与题目不能留空。

`examAlignment` 包含 `exam, paper, taskType, scope, criteria, sources, gaps`。`criteria` 每项为 `{id, label, requirement, sourceIds}`；`sources` 每项为 `{id, title, url}`，只用经过核查且确实支持相应要求的来源。`gaps` 为尚未覆盖的考试能力/条件说明。任务的 `examTargets` 引用 criteria 的 ID，`examUse` 解释本题怎样练到考试行为，`practiceMode` 为 `micro` 或 `exam-task`。微练习不要标为完整考试任务。

结构校验只能检查引用与字段，不能证明高拟合。发布前还要人工审查原料是否准确、题目是否测到目标、迁移是否真实、参考答案是否成立，以及反馈能否解释下一步。
